# BeeBranch 0.4.0 — P3

## Annulations explicites

- Undo/redo couvre la matrice Git : commit, amend, checkout, branches, tags,
  remotes, stash create, worktrees, merge/rebase/cherry-pick/revert terminés et
  en cours (abort typé), reset soft/mixed.
- Aucune sauvegarde applicative : seuls les refs, index et objets Git sont
  restaurés. Une précondition violée refuse sans effet.
- Un échec partiel affiche l'étape, la commande et le SHA de récupération
  (`git reflog`). Une restauration interrompue est marquée au démarrage et
  n'est jamais retentée automatiquement.

## Glisser-déposer

- Déposer une branche sur une autre ouvre un aperçu merge/rebase : commits
  concernés, fast-forward, worktree propre ou non, conflit d'extraction.
- Aucune mutation avant confirmation. Une annulation avant le drop ne change
  rien. Les conflits restent résolus dans la vue Conflits.
- Les commits du plan de rebase se réordonnent par glisser-déposer.

## Design system et accessibilité

- Tokens complets (espacement, typographie, profondeur, mouvement), thèmes
  clair/sombre/système, densité compacte ou confortable.
- Primitive de dialogue unique (piège de focus, restauration du focus, fond
  inert) et bouton de design system.
- Lien d'évitement, navigation clavier, messages d'erreur annoncés, contrastes
  vérifiés automatiquement dans les deux thèmes.

## Gros dépôts

- Le graphe consomme `git log` en flux : les pages profondes ne parcourent plus
  tout le préfixe. Sur `linear-1m`, l'ajout de 10 pages passe de 38,6 s à 18 ms
  (mesure locale, corpus déterministe).

## Workspaces

- Groupes locaux de 20 dépôts maximum, fetch/pull multi-dépôts avec quatre
  travailleurs bornés, résultat par dépôt, échec isolé, sessions fermées après
  l'action.

## Distribution

- Packaging Windows/macOS/Linux, signature et notarisation macOS, signature
  Windows, artefacts de mise à jour signés.
- Mise à jour signée : une signature absente ou invalide est refusée.
- Rollback signé via `rollback.json` (version précédente conservée).
- Aucune télémétrie : audit automatisé des sources, seules les connexions
  GitLab, Git et le manifeste de mise à jour sont possibles.

## Limites

- Les tests de signature, d'installation et de rollback sont exécutés dans la
  matrice CI ; l'installation sur machine propre n'est pas reproductible dans
  l'environnement de développement.
