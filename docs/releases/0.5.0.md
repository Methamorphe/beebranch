# BeeBranch 0.5.0

## Resize the interface

- Every divider can be dragged: navigation (180–420 px), References column,
  graph width, Author and Date columns, detail or commit
  preparation panel (300–760 px).
- Widths are remembered and reclamped to the window size. A
  double-click on a divider, or “Reset columns” in the
  graph options, restores the defaults.
- With the keyboard: ←/→ arrows when the divider has focus.

## Compare two commits

- Enable “Multiple selection”, check two commits, then “Compare A → B”.
- The diff runs from the first checked commit to the second and opens in the
  Comparison view. No repository mutation is performed.

## Date column

- The commit date (the committer's, not the author's) is always
  displayed to the right of the author.
- The old “Date” checkbox in the display options is removed: the column is
  permanent and resizable.

## Graph and branches

- Each commit is a strip tinted with its branch color;
  selection strengthens the tint and adds an accent bar on the left.
- References become chips colored by type — accent for
  HEAD, lane color for a local branch, information for a remote
  branch, warning for a tag — with the corresponding icon.
- Multiple references appear side by side; overflow becomes `+N` and
  opens the full list.
- Nodes are outlined to stand out from lanes, with an accent halo on
  HEAD. The branches column follows the longest label without ever
  crowding the commit subject.

## Merge with pending changes

- Dragging a branch onto another now works even with
  uncommitted changes: tracked changes are stored in an
  automatic stash (`BeeBranch auto-stash …`), the merge runs, then the
  stash is reapplied immediately.
- If the merge or reapplication conflicts, the stash is retained and
  its selector is displayed; nothing is lost.
- Undo reapplies the stash in addition to undoing the merge.
- Untracked files are neither stashed nor moved. Rebase remains
  rejected when tracked files are modified.

## GitLab: reuse the Git credential

- If `git clone` already works over HTTPS on this workstation, BeeBranch reuses
  the credential at startup: `url.<base>.insteadOf` and the `store`
  helper's files, including `~/.git-credentials`.
- An existing `glpat-` token is therefore enough to list projects and clone without
  reentering it. The session displays “via Git” and the “Disconnect” button
  disappears: Git still manages the secret.
- The token is neither copied into the OS keychain, written to the database, nor logged.
  A GitHub credential is never mistaken for a GitLab token, and a
  configured instance accepts only the credential for its own host.
- “Change instance” saves a new token in the OS keychain, as
  before.

## Clone: choose the directory

- The destination field offers “Browse…” and opens the system directory
  picker; the repository name is appended to the chosen directory.
- Manually entering the path remains possible.

## Local changes up to date without fetch

- The file watcher now invalidates the repository status, not just
  the working copy, on every file write and every index
  change.
- The “Local changes” summary and status bar refresh
  immediately after an external change or a `git add`, without
  a manual refresh.

## Update

- Same signing key as versions 0.4.x: from the installed
  application, Settings → Updates offers 0.5.0 and “Return to the
  previous version” goes back to 0.4.4 via `rollback.json`.
- Non-notarized macOS Apple Silicon build: Gatekeeper requests permission
  on first launch (`xattr -dr com.apple.quarantine /Applications/BeeBranch.app`).
