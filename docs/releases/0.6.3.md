# BeeBranch 0.6.3

## Amender un commit HEAD depuis le graphe ou le diff

- Le menu contextuel d’un commit HEAD et son nom dans l’en-tête du diff
  proposent « Amender ce commit… ».
- La boîte de dialogue reprend le message (éditable), inclut les fichiers
  préparés, rappelle que l’historique est réécrit et passe par le flux amend
  existant : hooks, signature, undo.
- L’action n’apparaît que pour HEAD et jamais pendant une opération Git ou avec
  des conflits en cours.

## Les fichiers Markdown se lisent rendus

- Dans le diff d’un fichier `.md`, un bouton « Rendu » affiche le document mis
  en forme : titres, listes, tableaux, citations et code. « Diff » ramène au
  patch sans recharger le fichier.
- Le contenu est lu à la révision du diff — copie de travail, index, commit ou
  extrémité d’une comparaison A → B — jamais depuis une autre version.
- Le rendu construit des éléments React : le HTML brut est ignoré, les images
  restent bloquées pour éviter toute requête distante et seuls les liens
  `https` s’ouvrent dans le navigateur système.

## Notes de version rendues

- Les notes du manifeste signé viennent de `docs/releases/*.md` : les réglages
  affichaient le Markdown brut. Les titres, listes, gras et code sont désormais
  rendus, avec la même politique de sécurité que les fichiers du dépôt.

## Corrections

- **Double-clic sur une branche distante d’un commit partagé** : le double-clic
  dans le graphe activait la première référence décorant la ligne au lieu du
  badge visé, donc parfois une autre branche locale à son commit courant. Le
  badge sous le curseur est désormais résolu ; une branche locale de suivi en
  retard reste replacée sur le commit distant avant la checkout.
- **Un fichier cliqué dans un commit ouvre son propre diff** : la commande de
  diff ignorait le chemin pour la cible `commit` et renvoyait le patch entier,
  dont la vue affichait toujours le premier fichier. Le chemin filtre désormais
  la sortie, commit racine sans parent compris.
- **Comparaison A → B** : le pied du graphe s’efface pendant la comparaison,
  puis revient à sa fermeture, pour laisser toute la hauteur à l’inspecteur et
  au patch.

## Vérifications

- `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --
  -D warnings`, `cargo test --workspace`, `npm run build`, `npm run lint`,
  `npm run ui:smoke` et `npm run audit:telemetry` passent avant publication.
- La preuve visuelle headless ouvre un fichier `.md` depuis les modifications
  locales, bascule en « Rendu », contrôle le titre, le gras, le tableau, le
  lien et l’absence de script ou d’image distante, puis vérifie que la lecture
  cible bien la révision `worktree` ; les notes de version sont aussi
  contrôlées rendues dans les réglages.
- Elle couvre l’amendement depuis le graphe et le diff : présence réservée à
  HEAD, message prérempli, fichiers préparés annoncés et appel `commit_create`
  avec le mode amend.
