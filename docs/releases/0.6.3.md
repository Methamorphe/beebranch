# BeeBranch 0.6.3

## Amend a HEAD commit from the graph or the diff

- A HEAD commit’s context menu and its name in the diff header
  offer “Amend this commit…”.
- The dialog reuses the message (editable), includes the
  staged files, recalls that history is rewritten and goes through the existing
  amend flow: hooks, signing, undo.
- The action appears only for HEAD and never during a Git operation or with
  conflicts in progress.

## Markdown files read rendered

- In the diff of a `.md` file, a “Rendered” button displays the formatted
  document: headings, lists, tables, quotes and code. “Diff” returns to the
  patch without reloading the file.
- The content is read at the diff revision — working copy, index, commit or
  an A → B comparison endpoint — never from another version.
- Rendering builds React elements: raw HTML is ignored, images
  remain blocked to avoid any remote request, and only `https`
  links open in the system browser.

## Rendered release notes

- The signed manifest's notes come from `docs/releases/*.md`: settings
  displayed raw Markdown. Headings, lists, bold and code are now
  rendered, with the same security policy as repository files.

## Fixes

- **Double-click on a remote branch of a shared commit**: double-click
  in the graph activated the first reference decorating the row instead of the
  targeted badge, and therefore sometimes another local branch at its current commit. The
  badge under the cursor is now resolved; a local tracking branch that is
  behind remains moved to the remote commit before checkout.
- **A file clicked in a commit opens its own diff**: the diff
  command ignored the path for the `commit` target and returned the entire patch,
  whose view always displayed the first file. The path now filters
  the output, including the root commit with no parent.
- **A → B comparison**: the graph footer fades during the comparison,
  then returns when it closes, to leave the full height to the inspector and
  the patch.

## Verifications

- `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --
  -D warnings`, `cargo test --workspace`, `npm run build`, `npm run lint`,
  `npm run ui:smoke` and `npm run audit:telemetry` pass before publication.
- The headless visual evidence opens a `.md` file from local
  changes, switches to “Rendered”, checks the heading, bold, table,
  link and the absence of scripts or remote images, then verifies that the read
  targets the `worktree` revision; release notes are also
  checked rendered in settings.
- It covers amending from the graph and the diff: presence restricted to
  HEAD, prefilled message, staged files announced and `commit_create`
  call with amend mode.
