# BeeBranch 0.7.1

## Onglet d'ouverture de dépôt

- ⌘/Ctrl + T (ou le bouton `+` des onglets) ouvre l'onglet d'accueil avec le
  champ « Rechercher un dépôt récent… » déjà focalisé ; la requête repart à zéro
  à chaque nouvel onglet.
- Le filtre porte sur le nom et le chemin du dépôt, la liste affiche
  « N sur M dépôts », Entrée ouvre le premier résultat, et l'absence de
  correspondance est signalée par un message.
- Le raccourci « Nouvel onglet » apparaît dans Préférences → Raccourcis et dans
  la palette de commandes.

## Pull, fetch et push : les échecs ne sont plus silencieux

- Le moteur vérifie désormais le code de sortie des commandes de
  synchronisation. Un `git pull` refusé — branche divergente, avance rapide
  impossible, identifiants refusés, fichier non suivi dans le chemin — remonte
  une erreur avec la sortie Git complète. Auparavant l’opération était annoncée
  « terminée » sans aucun changement, ce qui donnait l’impression que le pull
  ne faisait rien.
- Deux codes d’erreur dédiés aux refus de pull : « Le pull n'a pas pu s'intégrer
  en avance rapide » (`pull.ff=only` et branches divergentes) et « Git exige une
  stratégie pour réconcilier les branches divergentes ». Les autres refus
  réutilisent les messages existants (authentification, worktree sale, fichiers
  non suivis qui seraient écrasés, dépôt occupé).

## Résultat du pull visible

- La barre d’outils indique ce que le pull a réellement fait :
  `Pull : déjà à jour.`, `Pull : abc1234 → def5678.`, ou
  `Pull incomplet : N commits encore en retard.` quand Git a réussi sans
  intégrer ce qu’il venait de récupérer.
- Ce message est lié au dépôt qui l’a produit : il disparaît quand on change
  d’onglet et ne décrit plus un autre dépôt.

## Configuration Git respectée

- La stratégie de pull suit l’ordre de Git : `branch.<nom>.rebase`, puis
  `pull.rebase`, puis `pull.ff`. Seul `pull.rebase` était lu et `--no-rebase`
  était imposé, ce qui forçait une fusion chez les utilisateurs configurés en
  rebase ou en `pull.ff=only`.

## Mise à jour

- Bundles macOS signés et notariés, manifeste `latest.json` signé (minisign) et
  `rollback.json` conservant la version 0.7.0 pour revenir en arrière depuis
  Réglages → Mises à jour.
