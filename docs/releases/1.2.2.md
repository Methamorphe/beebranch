# BeeBranch 1.2.2

Readability of the history, plus the tag navigation that 1.2.1 left broken.

## Tag rows reveal their commit

- Picking a tag in the repository tree now selects the commit it points at,
  scrolls the history to that row when it sits outside the viewport, and opens
  its detail.
- An annotated tag stores a tag object, and that oid is never a row of the
  history: the previous selection landed nowhere and the inspector stayed
  empty. `for-each-ref` now also reports the peeled commit
  (`%(*objectname)`), and a tag row selects that oid. Lightweight tags keep
  pointing at their commit directly.

## Reference pills in the graph

- Branch, remote and tag pills keep the hue of the rail they sit on but are now
  filled solid instead of a 20–32 % tint, with the label and glyph in whichever
  ink — near-black or near-white — has the higher WCAG ratio on that fill. A
  badge reads as the same colour as its line in the history.
- Two light-theme lanes sat between the two inks (neither reached 4.5:1), so
  those pills are darkened just enough to clear AA. Floor: 4.65:1 in the light
  palette, 6.0:1 in the dark one, locked by `scripts/reference-pill-check.ts`.
- Author avatars use the same contrast helper, so initials and pills can no
  longer drift apart.

## Summary character counter

- The commit panel and the amend dialog show how many characters remain for the
  first line of the message, capped at the conventional 72-character Git
  subject. The count turns into a warning once the limit is exceeded; the body
  stays free-form.

## Notes

- No telemetry added; no preference migration; no format change.
- The headless UI smoke now covers the tag reveal end to end: selection, scroll
  and detail, on a tag whose commit is below the fold.
