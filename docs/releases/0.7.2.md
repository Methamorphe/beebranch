# BeeBranch 0.7.2

## Repository opened on Windows

- Fixes “The repository is not open. Open the repository before reading its status.”
  that appeared when opening any repository on Windows: read
  commands (state, status, refs, graph) could no longer find the
  session that had nevertheless been created.
- Cause: a repository identifier is a hash of its path, and the two
  forms of the same directory did not match. `fs::canonicalize` returns a
  *verbatim* path (`\\?\C:\Dev\repo`) while `git rev-parse
  --show-toplevel` returns `C:/Dev/repo`. The session registry was indexed
  by the first form, the identifier returned to the interface by the second:
  every read failed. On macOS and Linux both forms are identical,
  hence a bug invisible outside Windows.
- The registry is now indexed by the session identifier itself, and
  a repository's identity normalizes the verbatim prefix, separator
  style, drive letter case and a trailing separator. POSIX paths
  keep their exact spelling: macOS/Linux identifiers already stored
  in preferences and the journal do not change.
