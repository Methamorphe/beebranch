# BeeBranch 1.2.1

Two Windows-only defects fixed. No feature change and no data migration.

## Custom wallpaper

- The chosen image was read and persisted but never displayed. The cause is the
  rendering engine: Chromium — hence WebView2 on Windows — silently discards any
  CSS custom property value above 2 MiB, less than the base64 of an ordinary
  photo, while WebKit (macOS) accepted it. The image is now applied directly on
  its layer; the presentation options (fit, dim, blur) stay variables.
- The custom splash screen had the same defect and showed nothing but its veil;
  it is fixed the same way.
- The dim and blur sliders no longer rewrite the image on every movement: only
  the presentation changes, the payload is not re-encoded.

## Token creation link

- “Create a token” opened a File Explorer window instead of the forge. The link
  went through `explorer.exe`, which splits its arguments on commas: GitLab and
  GitHub token URLs carry a scope list (`scopes=api,read_user,read_repository`),
  interpreted as folder items. Opening now goes through `ShellExecuteW`, i.e.
  the browser registered for `https`, with no command-line parsing.
- Validation is unchanged: only `https` URLs without control characters or
  whitespace are opened.

## Notes

- The release notes are published in `latest.json` and in the GitHub release,
  as for previous versions.
- No telemetry added; no preference migration.
