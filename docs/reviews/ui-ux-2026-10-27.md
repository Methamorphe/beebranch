# Revue UI / UX et interactions — 27 octobre 2026

## Direction retenue

Le graphe est l’espace de travail principal. Les modifications locales et le prochain commit sont accessibles dans son panneau droit, comme demandé dans les références GitKraken fournies. Aucun écran « Modifications » supplémentaire n’est nécessaire dans la navigation.

- Navigation quotidienne : historique, branches, stash, merge requests, recherche. Les outils avancés et préférences sont repliés par défaut. Les conflits apparaissent lorsqu’ils nécessitent une intervention. Les anciennes entrées commit/diff ne sont plus des destinations autonomes de la palette.
- Ligne « Modifications locales » en tête du graphe : retour aux fichiers et au prochain commit. Sélection d’un commit : inspecteur à droite. Fermeture de l’inspecteur : retour à la préparation.
- Fichiers répartis entre « À préparer » et « Prêts à committer », listes compactes avec défilements indépendants. Action principale +/− ; actions rares dans un popover. Les abandons restent explicitement confirmés.
- Clic sur un fichier : aperçu et staging par ligne/hunk dans la zone centrale, sans quitter le dépôt ; fermer cet aperçu restitue le graphe. Le message de commit reste disponible à droite. Les brouillons sont conservés en mémoire pendant les navigations, pas après fermeture de l’application.
- Historique : messages en 15 px, lignes de 30 px, colonnes stables pour références/graphe/message, métadonnées optionnelles, survol et sélection distincts. Les diagnostics techniques ne recouvrent plus les commits. Toutes les branches et tags sont affichés par défaut.
- Police d’interface Open Sans, vérifiée dans les styles de l’installation locale de GitKraken. Chargement local depuis `@fontsource/open-sans` ; monospace réservé notamment au code et aux SHA.
- Menu contextuel : lignes d’actions, titres tronqués, placement mesuré et borné dans la fenêtre, défilement si nécessaire, navigation par flèches, Échap et fermeture au clic extérieur.
- Dialogues communs : focus initial, confinement du focus, restauration au déclencheur, prévention des raccourcis ouvrant une seconde modale. Les commandes indisponibles ne s’exécutent pas avec Entrée.
- Mouvements courts (120–180 ms), limités aux retours d’interaction, popovers et dialogues. Respect de `prefers-reduced-motion`.
- Fenêtres étroites : navigation compacte et panneaux empilés, sans débordement horizontal global.

## Validation

- `npm run build` : compilation TypeScript et bundle Vite.
- `npm run lint` : aucune erreur ; avertissements React non bloquants à traiter séparément.
- `npm run ui:smoke -- target/ui-after` : bundle de production dans Chromium avec IPC Tauri simulé. 44 contrôles UX réussis, en complément des parcours P1/P2 existants : staging fichier/ligne, conservation du brouillon, retour au graphe, clavier/modales, commandes indisponibles, placement des menus aux coins, tailles 1440/1024/768/390 px, thèmes et réduction des animations.
- Captures et résultats détaillés : `target/ui-after/`, notamment `ux-history.png`, `ux-history-selected.png`, `ux-context-menu-1440.png`, `ux-context-menu-390.png`, `ux-changes.png`, `ux-history-light.png`, `ux-checks.json`.

Ces vérifications UI n’exécutent pas de mutations sur un vrai dépôt et ne remplacent pas le dogfooding de l’application Tauri. Aucune parité complète avec GitKraken ni garantie de performance en production n’est déduite des données simulées. Le travail parallèle sur l’accueil/clonage a été conservé.


## Deuxième revue : densité et lisibilité

Comparaison visuelle à 1440 × 900 avec la première passe et la référence GitKraken : la première passe donnait trop de poids aux séparations, aux métadonnées et aux contrôles, avec seulement 16 commits visibles et des fichiers en 12 px.

- Barre de filtres intégrée à l’en-tête du graphe ; sélection multiple, auteur et date regroupés dans les options d’affichage. Les informations restent disponibles.
- Références : 140 px au lieu de 180 ; graphe d’une seule lane : 56 px au lieu de 88. Le message reçoit l’espace gagné ; auteur et date ne réduisent plus sa largeur par défaut.
- Messages : 15 px au lieu de 14, rangées de 30 px au lieu de 36, séparateurs horizontaux supprimés. 22 commits visibles dans la capture de référence, au lieu de 16.
- Fichiers : 14 px au lieu de 12, rangées de 29 px. Le nom de fichier reste visible quand le dossier doit être tronqué. Filtre et en-têtes plus compacts.
- Éditeur du commit : texte en 14 px, zone de saisie plus haute, action principale sur toute la largeur. Modèle, identité, signature et options rares regroupés sous une seule ouverture.
- Changements de couleur instantanés pour les boutons : pas de contraste intermédiaire entre un fond de sélection et un texte mis à jour. Les animations de dialogues/popovers restent respectueuses de la réduction des animations.

Captures et validation de cette passe : `target/ui-density/`. Le script mesure aussi la hauteur disponible, la place réservée aux colonnes, la taille des fichiers et la position du premier commit. Les contrôles fonctionnels/clavier/responsive antérieurs sont conservés.

Validation finale de densité : 49 contrôles UX réussis. À 1440 × 900 : premier commit à 191 px, 21 lignes complètes (22e partielle), colonnes références/graphe à 140/56 px, 645 px pour le message, fichiers à 14 px sur des rangées de 29 px. Build réussi, lint sans erreur avec avertissements React non bloquants.

## Visibilité selon la sélection

La ligne locale n’est rendue que si le dépôt comporte des fichiers préparés, modifiés, nouveaux ou en conflit. L’ouverture d’un dépôt ne sélectionne plus implicitement cette ligne. Le panneau droit apparaît uniquement pour un commit sélectionné ou pour la ligne locale explicitement sélectionnée. Fermer l’inspecteur restitue le graphe seul. Lorsque la dernière modification disparaît, l’aperçu local et la préparation se ferment automatiquement. Les brouillons restent conservés en mémoire. Le parcours du premier commit reste accessible sur un dépôt sans historique.

Les scénarios supplémentaires (dépôt propre, largeur complète, sélection/désélection, apparition et disparition des modifications) sont vérifiés dans `target/ui-selection/`.

## Barre supérieure inspirée de la référence GitKraken

- Première rangée : ouverture de dépôt, marque compacte, onglets avec fermeture, ajout de dépôt, réglages et profil. Le champ de recherche ne prend plus la place des onglets.
- Deuxième rangée : sélecteurs du dépôt ouvert et de la branche à gauche ; Fetch/Pull/Push, branches, stash/pop et terminal avec libellé au-dessus de l’icône ; actions secondaires et recherche à droite.
- Le sélecteur de dépôt utilise les sessions ouvertes. Le sélecteur de branche permet un checkout ou l’accès à la gestion des branches. Stash ouvre sa préparation, Pop cible le dernier stash disponible et le terminal utilise l’outil configuré.
- Les noms longs sont tronqués, les onglets défilent horizontalement, et les actions restent accessibles par tabulation lorsque la fenêtre est étroite.
- Vérification UI : `target/ui-topbar/`. Les nouveaux boutons Git et terminal sont vérifiés via des appels IPC simulés ; aucune mutation réelle n’est effectuée par le script.

## Branches regroupées dans le graphe

- Survol d’un badge : liste interactive de toutes les références du commit, avec les types locale/distante/tag. La liste reste accessible en déplaçant le pointeur dessus et ne déborde pas de la fenêtre.
- Double-clic sur le badge d’une branche : checkout. Double-clic sur une branche masquée dans la liste : checkout de cette référence précise. Entrée/Espace permettent la même action au clavier.
- Une branche distante utilise sa branche locale de suivi lorsqu’elle existe. Sinon, une branche locale est créée depuis la référence distante exacte et son upstream est configuré explicitement. Une collision avec une autre branche locale est signalée, sans la remplacer.
- Les tags, références symboliques et noms ambigus ne déclenchent pas un checkout de branche. La liste utilise les noms complets pour distinguer les décorations courtes dupliquées de Git. Le checkout est sérialisé côté UI pendant l’opération ; les erreurs Git restent visibles.
- Vérifications : `target/ui-refs/` et `ux-branch-hover.png`. Tests UI avec IPC simulé pour survol, maintien de la liste, double-clic visible/masqué, suivi distant, collision et tag homonyme. Le cas des décorations courtes dupliquées a également été reproduit dans un dépôt Git temporaire isolé.

## Ouverture par sélecteur natif de dossiers

Les points d’entrée d’ouverture (dossier, +, accueil, menu du dépôt, palette, ⌘O/Ctrl+O) ouvrent directement le sélecteur de dossiers du système via le plugin officiel Tauri Dialog. Le formulaire manuel de chemin a été supprimé. Une sélection ouvre et valide le dépôt ; une annulation conserve la session ; une erreur reste affichée dans l’application. Un garde empêche deux sélecteurs simultanés. Les dépôts récents restent accessibles depuis l’accueil.

Plugin Dialog 2.4.2 enregistré dans le bootstrap Tauri ; capacité limitée à `dialog:allow-open`. Validation : build frontend réussi, `cargo check -p beebranch` réussi, format du bootstrap Rust vérifié, lint sans erreur. Le contrôle de format global signale des différences dans d’autres sources en cours de modification, laissées intactes. Les 77 contrôles UI/IPC simulés passent, dont sélection, annulation, erreur Git, anti-doublon et raccourci d’ouverture (`target/ui-picker/`). La boîte OS elle-même n’est pas inspectée dans les tests Chromium ; la tentative d’accès à l’application native n’a pas trouvé d’application BeeBranch enregistrée auprès du contrôleur UI.
