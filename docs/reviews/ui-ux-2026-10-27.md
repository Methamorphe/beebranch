# UI / UX and interaction review — October 27, 2026

## Chosen direction

The graph is the main workspace. Local changes and the next commit are accessible in its right panel, as requested in the supplied benchmark references. No additional “Changes” screen is needed in navigation.

- Daily navigation: history, branches, stash, merge requests, search. Advanced tools and preferences are collapsed by default. Conflicts appear when they require intervention. The former commit/diff entries are no longer standalone palette destinations.
- “Local changes” row at the top of the graph: return to files and the next commit. Selecting a commit: inspector on the right. Closing the inspector: return to preparation.
- Files split between “To stage” and “Ready to commit,” compact lists with independent scrolling. Primary action +/−; rare actions in a popover. Discards remain explicitly confirmed.
- Clicking a file: preview and line/hunk staging in the central area, without leaving the repository; closing this preview restores the graph. The commit message remains available on the right. Drafts are kept in memory during navigation, not after the application closes.
- History: 15 px messages, 30 px rows, stable columns for references/graph/message, optional metadata, distinct hover and selection. Technical diagnostics no longer cover commits. All branches and tags are displayed by default.
- Open Sans interface font, verified in the styles of the local benchmark installation. Loaded locally from `@fontsource/open-sans`; monospace reserved for code and SHAs in particular.
- Context menu: action rows, truncated titles, measured placement bounded within the window, scrolling if needed, arrow navigation, Escape and closing on outside click.
- Shared dialogs: initial focus, focus containment, restoration to the trigger, prevention of shortcuts opening a second modal. Unavailable commands do not run with Enter.
- Short motion (120–180 ms), limited to interaction feedback, popovers and dialogs. Respects `prefers-reduced-motion`.
- Narrow windows: compact navigation and stacked panels, without global horizontal overflow.

## Second review: density and readability

Visual comparison at 1440 × 900 with the first pass and the benchmark reference: the first pass gave too much weight to separators, metadata and controls, with only 16 visible commits and files at 12 px.

- Filter bar integrated into the graph header; multiple selection, author and date grouped in display options. The information remains available.
- References: 140 px instead of 180; single-lane graph: 56 px instead of 88. The message receives the space gained; author and date no longer reduce its width by default.
- Messages: 15 px instead of 14, 30 px rows instead of 36, horizontal separators removed. 22 visible commits in the reference capture, instead of 16.
- Files: 14 px instead of 12, 29 px rows. The filename remains visible when the directory must be truncated. More compact filter and headers.
- Commit editor: 14 px text, taller input area, full-width primary action. Template, identity, signature and rare options grouped under a single disclosure.
- Instant button color changes: no intermediate contrast between a selection background and updated text. Dialog/popover animations continue to respect reduced motion.

Captures and validation for this pass: `target/ui-density/`. The script also measures available height, space reserved for columns, file size and the position of the first commit. Previous functional/keyboard/responsive checks are retained.

Final density validation: 49 successful UX checks. At 1440 × 900: first commit at 191 px, 21 complete rows (22nd partial), reference/graph columns at 140/56 px, 645 px for the message, files at 14 px on 29 px rows. Build successful, lint without errors with non-blocking React warnings.

## Visibility based on selection

The local row is rendered only if the repository contains staged, modified, new or conflicting files. Opening a repository no longer implicitly selects this row. The right panel appears only for a selected commit or the explicitly selected local row. Closing the inspector restores the graph alone. When the last change disappears, the local preview and preparation close automatically. Drafts remain preserved in memory. The first-commit flow remains accessible in a repository without history.

Additional scenarios (clean repository, full width, selection/deselection, changes appearing and disappearing) are verified in `target/ui-selection/`.

## Top bar inspired by the benchmark reference

- First row: open repository, compact branding, tabs with close buttons, add repository, settings and profile. The search field no longer takes space from the tabs.
- Second row: open repository and branch selectors on the left; Fetch/Pull/Push, branches, stash/pop and terminal with the label above the icon; secondary actions and search on the right.
- The repository selector uses open sessions. The branch selector allows checkout or access to branch management. Stash opens its preparation, Pop targets the latest available stash and the terminal uses the configured tool.
- Long names are truncated, tabs scroll horizontally, and actions remain accessible by tabbing when the window is narrow.
- UI check: `target/ui-topbar/`. The new Git and terminal buttons are checked via simulated IPC calls; no real mutation is performed by the script.

## Branches grouped in the graph

- Hovering over a badge: interactive list of all the commit's references, with local/remote/tag types. The list remains accessible when moving the pointer onto it and does not overflow the window.
- Double-clicking a branch badge: checkout. Double-clicking a hidden branch in the list: checkout of that exact reference. Enter/Space allow the same keyboard action.
- A remote branch uses its local tracking branch when one exists and resets its tip to the remote reference before checking it out (including if it is already active). Otherwise, a local branch is created from the exact remote reference and its upstream is configured explicitly. A collision with another local branch is reported, without replacing it.
- Tags, symbolic references and ambiguous names do not trigger a branch checkout. The list uses full names to distinguish Git's duplicate short decorations. Checkout is serialized on the UI side during the operation; Git errors remain visible.
- Checks: `target/ui-refs/` and `ux-branch-hover.png`. UI tests with simulated IPC for hover, keeping the list open, visible/hidden double-click, remote tracking, collision and same-name tag. The duplicate short decoration case was also reproduced in an isolated temporary Git repository.

## Opening through the native directory picker

The opening entry points (directory, +, home, repository menu, palette, ⌘O/Ctrl+O) open the system directory picker directly through the official Tauri Dialog plugin. The manual path form was removed. A selection opens and validates the repository; cancellation preserves the session; an error remains displayed in the application. A guard prevents two simultaneous pickers. Recent repositories remain accessible from home.

Dialog plugin 2.4.2 registered in the Tauri bootstrap; capability limited to `dialog:allow-open`. Validation: frontend build successful, `cargo check -p beebranch` successful, Rust bootstrap formatting checked, lint without errors. The global formatting check reports differences in other sources being modified, left untouched. The 77 simulated UI/IPC checks pass, including selection, cancellation, Git error, duplicate prevention and opening shortcut (`target/ui-picker/`). The OS dialog itself is not inspected in Chromium tests; the attempt to access the native application did not find a BeeBranch application registered with the UI controller.
