# P4 — Desktop parity backlog

**Status:** W1 cards shipped — 16 of 16; final validation pending.

| Card | Status |
|---|---|
| P4-T01 preferences, T02 editing, T03 squash, T04 signing, T05 hooks, T06 activity log, T07 hide/solo, T08 diff, T09 history, T10 live search, T11 sync, T12 tags, T13 worktrees, T14 submodules, T15 workspaces, T16 shortcuts | shipped |

Scope: the GitKraken **Desktop** documentation set only
([help.gitkraken.com](https://help.gitkraken.com/gitkraken-desktop/gitkraken-desktop-home/)),
minus everything that depends on GitKraken's cloud or AI platform.

Two kinds of cards:

- **Finish** — the behaviour exists but stops short of the documented one.
- **Add** — the behaviour does not exist at all.

Sizes: **S** ≤ 2 days, **M** ≈ 3–5 days, **L** ≈ 1–2 weeks, **XL** > 2 weeks
(single developer, tests included).

---

## Non-goals (excluded by product positioning)

Cloud Workspaces, Cloud Patches, Code Suggest, GitKraken AI, MCP, Agent
Sessions View, Team View, Insights/DORA, SSO/LDAP, Self-Hosted/Serverless
deployment, browser extension, GitLens, GitKraken CLI.

Rationale: [01-product-scope](../01-product-scope.md) and `README.md` — the
application is local-first, without vendor account, telemetry or AI.

## Wave 1 — Close the partial daily path

**Exit criterion:** a developer no longer needs a terminal or an external
editor for the operations GitKraken documents on the daily path; every card
meets the global DoD of [08-roadmap §2](../08-roadmap.md#2-definition-of-done-dod).

### P4-T01 — Complete the preferences surface

**Kind:** Finish · **Depends on:** — · **Size:** M

**Current state:** appearance, language, wallpaper, updates, external tools and
profiles exist; the documented preferences (encoding, diff/merge tool default,
terminal shell, hooks path, LFS, signing) do not.

**Deliverables**

- Encoding preference (UTF-8, UTF-16LE, Windows-1252, guess) used by every file read.
- Default diff and merge tool selection, applied to the external-tool actions.
- Preferences stored per profile when they are identity-bound, globally otherwise.
- A preferences schema with defaults, validation and reset.

**Acceptance criteria**

- Every preference is read back after a restart.
- An invalid value is refused with a stable error code, never silently defaulted.
- Removing a preference restores the documented default.
- No preference requires editing a configuration file.

**Tests:** preference round-trip, invalid values, reset.

### P4-T02 — In-app file editing

**Kind:** Finish · **Depends on:** P4-T01 · **Size:** L

**Current state:** files open in the external editor; the diff view can render
markdown but not edit or save.

**Deliverables**

- Edit mode from the diff, the command palette and the commit panel.
- Save, discard with confirmation, `editable` and unsaved markers.
- Stage from the editor: *save and stage* / *stage saved changes only*.
- Markdown preview toggle for `.md`, using the existing renderer.
- Encoding applied on write, never changed silently.

**Acceptance criteria**

- An edit is written byte-for-byte as typed; the stage action stages exactly the saved content.
- Discarding restores the previous content and leaves the index untouched.
- A binary or oversized file opens read-only with an explanation.
- Concurrent external modification is detected before writing and reported.
- The undo entry created by staging from the editor reverses cleanly.

**Tests:** save/stage/discard, conflict with external write, binary guard.

### P4-T03 — Squash a straight-line selection

**Kind:** Finish · **Depends on:** P2-T01 · **Size:** S

**Current state:** squashing exists only inside interactive rebase.

**Deliverables**

- Context-menu *Squash N commits* for a straight-line selection.
- Combined message pre-filled, editable before confirmation.
- Refusal with an explicit reason for merge commits and non-consecutive ranges.

**Acceptance criteria**

- The result matches the documented Git constraints (ancestor-descendant, consecutive, parent present).
- The resulting commit message contains every squashed message and can be amended.
- A refused selection changes nothing.
- The operation is undoable through the existing undo matrix.

**Tests:** squash of 2 and 3 commits, refusal cases, undo.

### P4-T04 — Commit signing UI

**Kind:** Finish · **Depends on:** P4-T01 · **Size:** M

**Current state:** `commit.signing` is read from Git configuration and respected
by the commit path; there is no interface to choose a key, sign by default or
inspect a signature.

**Deliverables**

- Signing key selection (GPG and SSH format), signing program path.
- *Sign commits by default* and *sign tags by default* preferences.
- Signature badge on the commit detail with its verification code (`GOODSIG`, `BADSIG`, …).
- Public-key export for upload to the hosting service.

**Acceptance criteria**

- A signed commit created from the application verifies with the configured key.
- An unavailable key blocks the commit before writing anything, with remediation.
- An unsigned repository is unaffected by enabling the preference for another one.
- The badge never claims validity it could not verify.

**Tests:** signed commit, missing key, invalid signature, SSH format.

### P4-T05 — Git hooks completion

**Kind:** Finish · **Depends on:** P1-T02 · **Size:** S

**Current state:** hooks run and their output is shown during the commit;
there is no skip toggle, no custom hooks path and no hook history.

**Deliverables**

- *Commit and skip hooks* option, explicit in the confirmation.
- Custom hooks path preference, per repository.
- Hook failures surfaced with exit code and output in the activity log.

**Acceptance criteria**

- A failing hook blocks the commit and leaves the index unchanged.
- Skipping is per commit and never persisted.
- A custom path is honoured for every hook-triggering action.

**Tests:** pre-commit failure, skip, custom path, non-executable hook.

### P4-T06 — Activity log

**Kind:** Finish · **Depends on:** P0-T09 · **Size:** M

**Current state:** the operation journal records business operations; there is
no timed application/repository log.

**Deliverables**

- Activity panel with *Application* and *Repository* tabs.
- Entry format: timestamp, action, duration in milliseconds, outcome.
- Extended mode including auto-fetch and background refreshes.
- Hook log entries linked to the failing action.

**Acceptance criteria**

- Every Git operation performed by the application produces exactly one entry.
- Repository entries are filtered to the active repository.
- The log is bounded and never grows without limit.
- No token, credential or file content appears in a log line.

**Tests:** entry per operation, filtering, rotation, redaction.

### P4-T07 — Hide and solo references

**Kind:** Finish · **Depends on:** P1-T09 · **Size:** S

**Current state:** the graph filters by one branch; references cannot be hidden
or soloed, and the choice is not persisted.

**Deliverables**

- Hide/show per reference and per section (local, remote, tags, stashes).
- Solo mode: soloed references hide every non-soloed one.
- Bulk show/hide from section headers, persisted per repository.

**Acceptance criteria**

- Hiding never changes the repository.
- Solo always leaves at least the current branch visible.
- The state survives a restart and is scoped to the repository.
- Filtering does not load more history than the unfiltered graph.

**Tests:** hide/solo persistence, scoping, graph reload cost.

### P4-T08 — Diff viewer polish

**Kind:** Finish · **Depends on:** P0-T06 · **Size:** S

**Current state:** hunk/inline/split, word diff, syntax highlight, hunk
navigation and line selection exist; word wrap, mini-map and file-to-file
navigation do not.

**Deliverables**

- Word wrap toggle, persisted.
- Mini-map of the file with the viewport window.
- Previous/next file navigation from the toolbar and keyboard.

**Acceptance criteria**

- Wrapping never changes line numbering or selection semantics.
- The mini-map stays accurate after staging a hunk.
- File navigation behaves identically in all three modes.

**Tests:** wrap toggle, minimap accuracy, navigation order.

### P4-T09 — File history and blame completion

**Kind:** Finish · **Depends on:** P2-T05 · **Size:** S

**Current state:** history with rename following, blame grouped by commit, blame
range and an entry from the diff exist; the Diff/File toggle, per-author
colouring, revision selection and the entry from the commit panel do not.

**Deliverables**

- Diff/File toggle inside blame.
- Author colour coding, stable per author.
- Revision selector, using the `revision` parameter already supported by the backend.
- *History* and *Blame* actions on each file of the commit panel.

**Acceptance criteria**

- The revision selector changes the history base without mutating the repository.
- Colours remain stable across reloads and repositories.
- Both entry points open the same file path.

**Tests:** revision base, colour stability, entry points.

### P4-T10 — Live search

**Kind:** Finish · **Depends on:** P1-T08, P4-T08 · **Size:** M

**Current state:** five modes are searched on explicit submit; results open the
graph but do not highlight the match; searches are not saved.

**Deliverables**

- Debounced live search for message/author/SHA with cancellation of the previous run.
- Match highlighted in the graph on selection.
- Saved searches per repository.
- Documented announcement of the searched depth and its ceiling.

**Acceptance criteria**

- Each keystroke cancels the previous search; no stale result is ever displayed.
- The highlighted commit is the one that was clicked.
- A saved search restores its mode, depth and scope exactly.

**Tests:** cancellation, stale response, highlight, persistence.

### P4-T11 — Synchronization completion

**Kind:** Finish · **Depends on:** P1-T04 · **Size:** M

**Current state:** fetch/pull/push with strategies, cancellation and
force-with-lease exist; auto-fetch, fetch-all, persisted strategy and the
outcome details do not.

**Deliverables**

- Auto-fetch with a configurable interval, pausable, silent on failure.
- Fetch every remote of the repository in one action.
- Default pull strategy preference, applied to the toolbar and the panel.
- Outcome details: branch tip before/after, remaining distance to upstream.

**Acceptance criteria**

- Auto-fetch never mutates a local branch.
- Fetch-all reports per-remote results without aborting the others.
- A cancelled operation still reports the revalidated remote state.
- No background fetch runs when the preference is off.

**Tests:** auto-fetch interval, fetch-all partial failure, cancellation, persistence.

### P4-T12 — Tags completion

**Kind:** Finish · **Depends on:** P2-T12 · **Size:** S

**Current state:** create (lightweight/annotated), push, delete locally and on a
remote exist; annotating an existing tag, fast-forwarding it, and filtering do not.

**Deliverables**

- *Annotate* an existing lightweight tag.
- Fast-forward move with refusal when the target is not a descendant.
- Tag search filter in the panel and the left panel.

**Acceptance criteria**

- Annotating never changes the tagged commit.
- A non-fast-forward move is refused with an explicit reason.
- The filter matches on name and message.

**Tests:** annotate, fast-forward, refusal, filter.

### P4-T13 — Worktrees completion

**Kind:** Finish · **Depends on:** P2-T04 · **Size:** S

**Current state:** create, open, lock, remove (with force), prune (dry-run and
real) exist; repair, remove-with-branch, prune options and search do not.

**Deliverables**

- `git worktree repair` for moved worktrees.
- *Remove worktree and delete its branch*, with typed confirmation.
- Prune with expiry and dry-run report listing what would be removed.
- Filter by branch or folder.

**Acceptance criteria**

- Repair never discards uncommitted work.
- Removing the branch is refused when it is checked out elsewhere or unmerged.
- The dry-run report matches the following real prune.

**Tests:** repair, remove-with-branch refusals, prune report.

### P4-T14 — Submodules completion

**Kind:** Finish · **Depends on:** P2-T11 · **Size:** S

**Current state:** add, init/update, sync, open and remove exist; auto-update and
the recursive option on single-entry actions do not.

**Deliverables**

- Auto-update preference (global and per repository).
- Recursive option honoured by single-entry update and sync.
- Explicit `--force` option on add, instead of an implicit force.
- Nested submodule expansion in the panel.

**Acceptance criteria**

- Auto-update never advances a pointer without an explicit action.
- A recursive single-entry update reports every nested entry it touched.
- A refused add leaves `.gitmodules` untouched.

**Tests:** auto-update, recursion, forced add.

### P4-T15 — Workspaces completion

**Kind:** Finish · **Depends on:** P3-T05 · **Size:** M

**Current state:** local workspaces with aggregate state, open-all and
fetch/pull over every repository exist; subset selection, batch clone/locate,
import and directory sync do not.

**Deliverables**

- Select a subset of repositories for a batch action.
- Batch open in external editor, clone missing repositories, locate moved ones.
- Import and export of a workspace, including a `.code-workspace` import.
- Per-workspace pull strategy and remote.

**Acceptance criteria**

- A batch action reports one result per repository, ordered, without aborting on failure.
- Import never duplicates an existing repository.
- Located repositories keep their identity and recent entries.

**Tests:** subset batch, import/export, partial failure, re-import.

### P4-T16 — Keyboard shortcuts

**Kind:** Finish · **Depends on:** P2-T06 · **Size:** S

**Current state:** a documented handful exist (undo/redo, palette, workspace,
new tab); there is no complete set, no cheat sheet, no conflict detection.

**Deliverables**

- Every palette command reachable by a shortcut where one is conventionally expected.
- Cheat-sheet panel generated from the same table as the bindings.
- Conflict detection at startup, with the conflicting pair reported.

**Acceptance criteria**

- The cheat sheet and the bindings cannot diverge (single source).
- No shortcut fires while a text field has focus unless it is a global one.
- Conflicts are refused at load time, not at first use.

**Tests:** binding table generation, focus guard, conflict refusal.

## Wave 2 — Review, providers, and issues

**Exit criterion:** a review can be conducted end to end — read the diff, comment,
request changes, approve, merge, check out — and every supported issue tracker
appears next to the repository.

### P4-T17 — Review workflow completion

**Kind:** Finish · **Depends on:** P2-T09 · **Size:** M

**Current state:** list, detail, approve/unapprove, merge (three strategies,
auto-merge), comments and pipelines exist; request changes, close/reopen,
title/description editing, reviewers/assignees/labels and draft⇄ready do not.

**Deliverables**

- *Request changes* review submission with a body.
- Close and reopen a request.
- Edit title and description; toggle draft ⇄ ready.
- Reviewers, assignees and labels: display and mutation at creation, where the provider allows it.

**Acceptance criteria**

- Each mutation is refused with the provider's reason when the token lacks the right.
- A closed request disappears from the open lists and remains reachable by URL.
- The detail view reflects the mutation without a manual refresh.
- No mutation is sent twice on a double click.

**Tests:** each mutation against wiremock, refused permission, idempotence.

### P4-T18 — Review diff and suggestions in-app

**Kind:** Add · **Depends on:** P4-T17, P0-T06 · **Size:** L

**Current state:** comments are written by typing a path and a line number; the
request diff is not displayed; GitHub suggestions cannot be authored.

**Deliverables**

- Diff of the request inside the app, reusing the existing diff viewer.
- Line comment from the diff selection, with side and line resolved automatically.
- GitHub suggestion block insertion from a selection.
- Pending comments grouped before submission, per provider capability.

**Acceptance criteria**

- A comment created from the diff lands on the displayed line (off-by-one forbidden).
- The suggestion block produces valid markdown for the provider.
- Deleting a selection before posting leaves no orphan comment.
- A provider without suggestions hides the action instead of failing.

**Tests:** line mapping on added/removed/context lines, suggestion payload, hidden capability.

### P4-T19 — Checkout a request, filter syntax

**Kind:** Finish · **Depends on:** P4-T17 · **Size:** S

**Current state:** checkout runs `git switch <branch>` in the active repository;
the documented filter syntax is replaced by four fixed scopes.

**Deliverables**

- Checkout that fetches the branch when missing and offers the remote to add.
- *Checkout in new worktree*.
- Filter grammar (`author:`, `label:`, `state:`, `reviewer:`, negation) with completion.

**Acceptance criteria**

- A branch from a fork is fetched into a named local branch, never left detached.
- An unknown filter token is reported, not ignored.
- The filter produces the same set as the provider query for the same tokens.

**Tests:** fork checkout, worktree checkout, grammar parsing, unknown token.

### P4-T20 — GitLab depth

**Kind:** Finish · **Depends on:** P2-T10 · **Size:** M

**Current state:** pipelines, jobs and bounded logs are read-only; approval has
no body; draft is creation-only.

**Deliverables**

- Choose a pipeline and load its jobs.
- Retry and cancel a job, with confirmation.
- Approve with an optional note; unapprove.
- Draft ⇄ ready on an existing MR.

**Acceptance criteria**

- Retrying is refused when the token lacks the right, with the provider message.
- Job logs remain bounded and streamed progressively.
- Approval state is refreshed from the provider, never assumed.

**Tests:** job retry/cancel, approval note, draft toggle, permission refusal.

### P4-T21 — GitHub checks and Actions

**Kind:** Finish · **Depends on:** P2-T09 · **Size:** M

**Current state:** checks and bounded logs are read-only; the badge appears only
for a request whose checks were loaded.

**Deliverables**

- Checks badge for every request in the list, within a bounded request budget.
- Workflow-run detail: jobs, steps, per-step log.
- Re-run failed jobs and cancel a run, with confirmation.

**Acceptance criteria**

- The badge reflects the worst check, never a stale one after a refresh.
- The list refresh stays within the documented rate budget (no per-request fan-out).
- A re-run is refused for a run that is not finished, with a clear message.

**Tests:** badge aggregation, pagination, re-run refusal, rate budget.

### P4-T22 — Issues: GitHub and GitLab

**Kind:** Add · **Depends on:** P4-T17 · **Size:** L

**Deliverables**

- Issue list, detail, comments, labels, assignees, milestones.
- Create, edit, close/reopen; filter by assignee, label, state.
- Issues of the repository shown next to its requests, and in the palette.

**Acceptance criteria**

- Cloud and self-hosted instances both work; GHES and GitLab self-managed use the same commands.
- Markdown rendering matches the comment renderer already in place.
- Offline degradation is explicit: the panel states it, it does not show an empty list.

**Tests:** list/detail/create/close, self-hosted URL derivation, offline.

### P4-T23 — Issues: Jira and Trello

**Kind:** Add · **Depends on:** P4-T22 · **Size:** L

**Deliverables**

- Jira Cloud and Data Center authentication (token, base URL).
- Issue list and detail bound to the repository, with a configurable JQL filter.
- Trello cards for the configured board.
- Issue keys detected in commit messages and branch names, linked in the UI.

**Acceptance criteria**

- Credentials live in the OS keychain only.
- A failing tracker never blocks the repository views.
- The issue link resolves to the configured instance, not to a public default.

**Tests:** authentication, JQL filter, link detection, failure isolation.

## Wave 3 — Workflow extensions

**Exit criterion:** the documented workflow features that do not require a
vendor account are available: Gitflow, LFS, terminal, Launchpad, deep links,
WSL 2, conflict prevention, favourites, palette coverage, accessibility.

### P4-T24 — Gitflow

**Kind:** Add · **Depends on:** P1-T03 · **Size:** M

**Deliverables**

- Initialize Gitflow with configurable branch names; create `main`/`develop` when missing.
- Gitflow panel: start and finish feature, release and hotfix.
- Finish semantics: merge into `develop` (feature), into `main` and `develop` plus tag (release), both without tag (hotfix).
- Tag prefix preference.

**Acceptance criteria**

- A finish is a single undoable operation or a documented multi-step sequence.
- Refuses to start when `main`/`develop` are dirty or missing in a non-recoverable way.
- The created tag follows the configured prefix and carries the release message.

**Tests:** init, start/finish of the three branch types, tag prefix, refusal cases.

### P4-T25 — Git LFS

**Kind:** Add · **Depends on:** P4-T01 · **Size:** M

**Deliverables**

- Capability detection (`git lfs version`) with an explicit unsupported state.
- Initialize LFS in an existing repository; initialize-with-LFS at creation.
- Tracking patterns (`*.psd`), LFS tag in the commit panel.
- LFS pull, prune and status from the toolbar menu.

**Acceptance criteria**

- Without the `git-lfs` binary, every LFS action is disabled with the reason.
- A tracked file is committed as a pointer, and the pattern lands in `.gitattributes`.
- Prune reports reclaimed space and never removes an object still referenced.

**Tests:** init, track, commit pointer, prune, missing binary.

### P4-T26 — Integrated terminal

**Kind:** Add · **Depends on:** P0-T01 · **Size:** L

**Deliverables**

- Embedded terminal panel with tabs, one set per repository/worktree.
- Working directory bound to the worktree; sessions survive a tab switch.
- Shell preference (PowerShell/Bash on Windows; ZSH/Bash elsewhere), font and size.
- Git command and flag completion; drag-and-drop of a path into the prompt.

**Acceptance criteria**

- A command typed in the terminal sees the same repository state as the UI.
- Switching worktree never reuses another worktree's session.
- Closing a session terminates the process; no orphan child remains.
- Terminal output is never written to the application log.

**Tests:** session isolation, process termination, shell selection, path drop.

### P4-T27 — Launchpad inbox

**Kind:** Add · **Depends on:** P4-T15, P4-T22 · **Size:** L

**Deliverables**

- Inbox across a workspace: pull/merge requests, issues, and repositories with uncommitted work.
- Personal view (created by me, assigned, review requested, mentioned).
- Pin, snooze with duration, snoozed tab.
- Saved views bound to the mode in which they were created.
- Quick actions: open in browser, checkout, checkout in worktree, close.

**Acceptance criteria**

- The inbox loads incrementally and never blocks the rest of the interface.
- Snoozing hides an item for its duration only, across restarts.
- A saved view restores its filters exactly, and is not visible in the other mode.
- An unreachable provider degrades to a per-source error, not an empty inbox.

**Tests:** aggregation, personal filter, snooze expiry, saved view scope, provider failure.

### P4-T28 — Deep linking

**Kind:** Add · **Depends on:** P0-T01 · **Size:** S

**Deliverables**

- `beebranch://` protocol registration on the three platforms.
- Links to repository, branch, commit, tag, and file-at-commit.
- Repository resolution: open, prompt to clone with a pre-filled URL, or choose among copies.

**Acceptance criteria**

- An unknown or malformed link opens the application without mutating anything.
- An already open repository is focused, not reopened.
- No link executes a command; it only navigates.

**Tests:** registration, each link kind, malformed link, multiple copies.

### P4-T29 — WSL 2 support

**Kind:** Add · **Depends on:** P4-T26 · **Size:** M

**Deliverables**

- Distribution detection and selection.
- Repository discovery and Git execution inside the distribution.
- Terminal bound to the distribution.
- Path translation between Windows and the distribution.

**Acceptance criteria**

- A repository opened through WSL behaves identically to a local one for every documented operation.
- Only repositories inside the distributions currently listed can be registered.
- An unavailable distribution is reported, never silently substituted.

**Tests:** discovery, path translation, operation parity, missing distribution.

### P4-T30 — Conflict prevention

**Kind:** Add · **Depends on:** P1-T05 · **Size:** M

**Deliverables**

- Background comparison of the current branch with its target branch.
- Alert listing overlapping files and lines; direct merge or rebase action.
- Branch patterns with `**` wildcard and `!` exclusion, stored per repository.
- Explicit "no conflict detected" state.

**Acceptance criteria**

- The comparison is bounded and cancellable; it never runs while another operation is in progress.
- The alert matches a real merge: the same files conflict when the merge is attempted.
- Disabling the feature stops all background work.

**Tests:** overlap detection, pattern matching, disabled state, bound.

*Out of scope:* organisation-wide detection between members (requires the cloud service).

### P4-T31 — Favorites and quick switching

**Kind:** Add · **Depends on:** P1-T07 · **Size:** S

**Deliverables**

- Mark a repository as favourite; dedicated section in repository management.
- `Ctrl/⌘+Alt+1…9` switching, with unavailable slots reported.
- Favourites included in the command palette.

**Acceptance criteria**

- Order is stable and user-controlled (explicit reorder, not insertion order).
- A missing repository keeps its slot and is reported as unavailable.
- The shortcut never opens a repository that is not registered.

**Tests:** ordering, slot assignment, missing repository.

### P4-T32 — Command palette coverage

**Kind:** Finish · **Depends on:** P2-T06 · **Size:** S

**Deliverables**

- Every user-facing action reachable from the palette, with availability and reason.
- Contextual ordering by view and selection.
- Recent commands first.

**Acceptance criteria**

- An unavailable command states why instead of disappearing silently.
- The palette never proposes an action that the current state refuses.
- Recent commands survive a restart.

**Tests:** coverage audit against the action registry, availability reasons, persistence.

### P4-T33 — Accessibility completion

**Kind:** Finish · **Depends on:** P3-T06 · **Size:** M

**Deliverables**

- Keyboard navigation of the commit graph (row focus, selection, context menu).
- Focus management in every dialog and panel, including return focus.
- Live-region announcements for long operations and errors.
- Contrast audit of every theme and density.

**Acceptance criteria**

- Every action reachable by mouse is reachable by keyboard.
- No focus trap escapes its dialog; escape always cancels.
- Automated contrast checks pass on both themes; manual screen-reader pass recorded.

**Tests:** keyboard paths, focus return, contrast, screen-reader checklist.

## Wave 4 — Remaining providers

**Exit criterion:** the two remaining documented providers work at the same
level as GitHub and GitLab for listing, detail, review and CI.

### P4-T34 — Bitbucket Cloud and Data Center

**Kind:** Add · **Depends on:** P2-T09, P4-T17 · **Size:** XL

**Deliverables**

- Client for both APIs, URL derivation, pagination, ETag cache.
- Pull requests: list, detail, diff, comments, approve, merge strategies.
- Pipelines: status and bounded logs.
- Repository ↔ project matching, including Data Center base URLs.

**Acceptance criteria**

- The provider registry exposes Bitbucket through the same interface as GitHub and GitLab.
- Self-hosted base URLs and CAs are supported.
- Unsupported capabilities are hidden, not emulated.

**Tests:** client against wiremock fixtures, URL derivation, capability matrix.

### P4-T35 — Azure DevOps

**Kind:** Add · **Depends on:** P4-T34 · **Size:** XL

**Deliverables**

- Client for Azure DevOps Services and Server.
- Pull requests: list, detail, threads, votes, completion.
- Builds: status and bounded logs.
- Work items read-only, as the issue counterpart.

**Acceptance criteria**

- Authentication (PAT) is stored in the keychain and never logged.
- Thread positions map to the displayed diff.
- Server and Services share one implementation selected by configuration.

**Tests:** client fixtures, thread mapping, PAT handling, Server/Services switch.

### P4-T36 — Self-signed certificates for any provider

**Kind:** Finish · **Depends on:** P4-T34 · **Size:** S

**Current state:** a CA can be provided per GitLab/GitHub instance; there is no
general certificate management.

**Deliverables**

- Import a CA bundle per instance, validated before storage.
- Certificate pin visibility: which instance uses which bundle.
- Explicit refusal message when a host cannot be verified.

**Acceptance criteria**

- Adding a CA never weakens verification for another host.
- A removed bundle stops being used immediately.
- A TLS failure names the host and the remediation.

**Tests:** CA import, isolation between instances, removal, TLS failure message.
