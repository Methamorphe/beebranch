# P1 — Task cards

Each card is self-contained. One card = one PR. Dependencies must be completed.

---

## P1-T01 — Status and file/hunk/line staging

**Objective:** enable the daily task of preparing a commit, without index corruption.

**Depends on:** P0-T04, P0-T05, P0-T06

**Deliverables**

- Status view: staged, unstaged, untracked, conflicts, renames.
- Stage/unstage by file.
- Patch engine: generation and application of hunk and line patches.
- File/hunk discard with explicit confirmation and preflight (irreversible action, no backup).
- Ignore (file/extension/directory) with explicit write.
- Refresh after each action and after external changes.

**Steps**

1. Wire up status and file actions.
2. Implement the patch engine (hunk then line).
3. Implement discard without an application-managed copy, with enhanced confirmation.
4. Implement ignore.
5. Regression tests on fixtures.

**Acceptance criteria**

- The index is consistent after each action (verified by `git diff`).
- CRLF, missing newline, rename, executable mode, Unicode: correct.
- An ambiguous patch fails without partial modification.
- Discard requires explicit confirmation and is announced as irreversible.
- Untracked file: never deleted by the application.
- No action blocks the UI.

**Tests**

- Patch engine unit tests (case matrix).
- Integration on fixtures.
- Performance PERF-07.

**Out of scope**

- 3-panel conflict editor.
- Interactive staging through code search.

**Expected evidence**

- Line-by-line staging demo + index tests.

## P1-T02 — Commit and amend

**Objective:** create and modify commits while respecting hooks and signing.

**Depends on:** P1-T01

**Deliverables**

- Message editor, amend, statistics.
- Hook execution and output display.
- Hook failure handling (commit not created, message preserved).
- Respect for `commit.gpgsign` and `user.signingkey`.
- Explicit error if identity is missing.

**Acceptance criteria**

- A failing hook prevents the commit and displays its output.
- Amend preserves or replaces the message according to the choice.
- Signing is applied if configured; no signature added otherwise.
- No implicit `--no-verify`.
- The commit appears in the graph after refresh.

**Tests**

- Fixtures with a successful/failed hook.
- Empty commit rejected unless `--allow-empty` is explicit.
- Signing configured / absent.

**Out of scope**

- AI message composition.
- Partial commit by file in this task (already covered by staging).

**Expected evidence**

- Tests + screenshot of hook output.

## P1-T03 — Local and remote branches

**Objective:** manage the branch lifecycle without loss.

**Depends on:** P0-T04

**Deliverables**

- Create, checkout, rename, delete.
- Remote branches, upstream, comparison.
- Preflight: current branch, merged, upstream, local work.
- Bulk actions (multiple deletion) with confirmation.

**Acceptance criteria**

- An unmerged branch requires strong confirmation.
- A current branch cannot be deleted.
- Checkout refuses if changes would be overwritten.
- The upstream is correctly displayed and editable.
- No remote branch deleted by mistake.

**Tests**

- Fixtures: merged/unmerged branches, detached, missing upstream.
- Rejection tests.

**Out of scope**

- Drag & drop (P3).

**Expected evidence**

- Status tests after each operation.

---

## P1-T04 — Fetch, pull and push

**Objective:** synchronize with remotes with progress, cancellation and clear errors.

**Depends on:** P1-T03

**Deliverables**

- Fetch, pull (ff-only/rebase according to config), push.
- Streamed progress and cancellation.
- Non-fast-forward detection.
- Explicit force-with-lease only.
- HTTPS credential helper and SSH support.
- Handling of auth, host key, network errors.

**Acceptance criteria**

- Visible progress during the operation.
- Cancellation: the repository remains in a valid state; the remote is revalidated.
- A non-fast-forward push is rejected with remediation.
- No force push without confirmation.
- No token in the remote configuration.

**Tests**

- Simulated local remote (bare) for fetch/push.
- Auth, host key, network failure.
- Cancellation while running.

**Out of scope**

- SSH key management.
- Pull with exotic strategies.

**Expected evidence**

- Fetch/push demo + cancellation tests.

## P1-T05 — Merge, rebase and basic conflicts

**Objective:** integrate branches and handle conflicts without loss.

**Depends on:** P1-T03, P1-T04

**Deliverables**

- Merge and rebase with preflight.
- Conflict detection, file list.
- Mark as resolved, `continue`, `abort`, `skip`.
- Open in the external editor/merge tool.
- Persistent display of the intermediate state.
- Recovery after restart.

**Acceptance criteria**

- A conflict-free merge completes or creates a commit according to the configuration.
- A conflict is visible and blocks incompatible actions.
- `abort` restores the state before the operation (or reports what cannot be restored).
- `continue` works after resolution.
- No unrelated local work is lost.

**Tests**

- Merge/rebase conflict fixtures.
- Abort/continue/skip.
- Restart during a conflict.

**Out of scope**

- 3-panel resolution (P2).
- Interactive rebase (P2).

**Expected evidence**

- Status tests + screenshots.

## P1-T06 — Stash

**Objective:** set aside and restore work without loss.

**Depends on:** P1-T01

**Deliverables**

- Create, list, apply, pop, drop.
- Stash visible in the graph.
- Pop conflict handling.
- Stash message.

**Acceptance criteria**

- A created stash is found after restart.
- A conflicting pop leaves the stash intact.
- A drop requests confirmation and retains a recovery reference.
- No untracked file lost without an explicit choice.

**Tests**

- Stash fixtures with staged/unstaged/untracked changes.
- Pop conflict.
- Drop and recovery.

**Out of scope**

- Partial stash by file (optional, only if measured as useful).

**Expected evidence**

- Status tests.

## P1-T07 — Multiple repositories

**Objective:** work on multiple repositories without status or memory leaks.

**Depends on:** P0-T03

**Deliverables**

- Repository tabs, recents, favorites.
- Isolated sessions, clean shutdown.
- Activity indicator per tab.
- Fast switching without unnecessary full reloads.

**Acceptance criteria**

- Five repositories opened alternately: no measurable leak, no cross-repository status.
- Closing releases the watcher, caches and processes.
- Errors in one repository do not affect the others.
- The active tab is restored on restart.

**Tests**

- PERF-09.
- Shutdown and leak test.
- Error isolation test.

**Out of scope**

- Workspaces (P3).

**Expected evidence**

- Memory measurements + tests.

## P1-T08 — Commit search

**Objective:** find a commit quickly without loading the entire history.

**Depends on:** P0-T04

**Deliverables**

- Search by message, SHA, author.
- Paginated results, navigation to the graph.
- Explicit depth and limit indicator.
- No freeze on large histories.

**Acceptance criteria**

- Correct results on fixtures.
- Search limited to a stated depth.
- No implicit full loading.
- Cancellation possible.

**Tests**

- Fixtures with varied messages/authors.
- PERF-12.

**Out of scope**

- Content search (P2).

**Expected evidence**

- Tests + measurement.

## P1-T09 — Graph interactions

**Objective:** make the graph actionable.

**Depends on:** P0-T05, P1-T03

**Deliverables**

- Commit/branch/tag selection.
- Context menu: checkout, create branch, compare, copy SHA, open MR.
- Basic filters (current branch, simple hide/solo).
- MR/CI badge.

**Acceptance criteria**

- No destructive action without confirmation.
- The graph remains smooth during interactions.
- The MR badge corresponds to the branch.

- Performance during interactions.

**Out of scope**

**Expected evidence**

- Demo + tests.

## P1-T10 — GitLab: MR list and creation

**Objective:** manage MRs from the application.

**Depends on:** P0-T07

**Deliverables**

- MR list (my MRs, to review, assigned, project).
- Minimal details (title, branches, authors, labels, status).
- Creation from a pushed branch.
- Open in the browser.
- Repository ↔ project association.
- Handling of 401/403/404/409/422 errors.

**Acceptance criteria**

- The list is paginated and filtered correctly.
- Creation fails cleanly if the branch has not been pushed.
- The form handles title, description, target, draft, source deletion.
- No token in the UI or logs.
- Offline: latest cached data, no queued mutation.

**Tests**

- HTTP contract + test instance.
- Real creation on a test project.
- Artifact security.

**Out of scope**

- Inline discussions, approvals, merge (P2).

**Expected evidence**

- Full recorded workflow + tests.

## P1-T12 — Destructive action safety

**Objective:** guarantee zero silent loss before full undo.

**Depends on:** P1-T01, P1-T03, P1-T05

**Deliverables**

- Centralized preflight.
- Confirmation dialogs with exact consequences.
- No application-managed backup: enhanced confirmation and explicit mention of irreversibility.
- Rejection if status is inconsistent.
- Destructive action log.

**Acceptance criteria**

- Every action in the §2 matrix of [07-reliability-security](../07-reliability-security.md) is covered.
- The number of affected files/commits is displayed.
- No untracked file is deleted by the application.
- Every irreversible action is identified as such before execution.

**Tests**

- Complete matrix.
- Full disk, permissions, inconsistent status.

**Out of scope**

- Full undo/redo (P3).

**Expected evidence**

- Tests + screenshots of dialogs.

## P1-T13 — External tools

**Deliverables**

- Detection of available editors/terminals.
- Open in the correct directory (worktree).
- External diff/merge tool configuration.

- The terminal opens in the worktree.
- A missing tool produces a clear error.

**Tests**

- Argument verification.

**Out of scope**

- Integrated terminal.

**Expected evidence**

- Tests + demo.

**Depends on:** P1-T01..T13

**Deliverables**

- Log of blockers and pain points.
