# P1 — Fiches de tâches

Chaque fiche est autonome. Une fiche = une PR. Les dépendances doivent être terminées.

---

## P1-T01 — Status et staging fichier/hunk/ligne

**Objectif :** permettre le geste quotidien de préparation d'un commit, sans corruption d'index.

**Dépend de :** P0-T04, P0-T05, P0-T06

**Livrables**

- Vue status : staged, unstaged, untracked, conflits, renommages.
- Stage/unstage par fichier.
- Patch engine : génération et application de patchs de hunk et de ligne.
- Discard fichier/hunk avec confirmation explicite et préflight (action irréversible, aucune sauvegarde).
- Ignore (fichier/extension/dossier) avec écriture explicite.
- Rafraîchissement après chaque action et après changement externe.

**Étapes**

1. Brancher le status et les actions fichier.
2. Implémenter le patch engine (hunk puis ligne).
3. Implémenter discard sans copie applicative, avec confirmation renforcée.
4. Implémenter ignore.
5. Tests de non-régression sur fixtures.

**Critères d'acceptation**

- L'index est cohérent après chaque action (vérifié par `git diff`).
- CRLF, absence de newline, renommage, mode exécutable, Unicode : corrects.
- Un patch ambigu échoue sans modification partielle.
- Discard exige une confirmation explicite et est annoncé comme irréversible.
- Fichier non suivi : jamais supprimé par l'application.
- Aucune action ne bloque l'UI.

**Tests**

- Unitaires patch engine (matrice de cas).
- Intégration sur fixtures.
- Performance PERF-07.

**Hors périmètre**

- Éditeur de conflits 3 panneaux.
- Staging interactif par recherche de code.

**Preuve attendue**

- Démo staging ligne par ligne + tests d'index.

## P1-T02 — Commit et amend

**Objectif :** créer et modifier des commits en respectant hooks et signature.

**Dépend de :** P1-T01

**Livrables**

- Éditeur de message, amend, statistiques.
- Exécution des hooks et affichage de la sortie.
- Gestion de l'échec de hook (commit non créé, message conservé).
- Respect de `commit.gpgsign` et `user.signingkey`.
- Erreur explicite si identité absente.

**Critères d'acceptation**

- Un hook en échec empêche le commit et affiche sa sortie.
- L'amend conserve ou remplace le message selon le choix.
- La signature est appliquée si configurée ; aucune signature ajoutée sinon.
- Aucun `--no-verify` implicite.
- Le commit apparaît dans le graphe après rafraîchissement.

**Tests**

- Fixtures avec hook réussi/échoué.
- Commit vide refusé sauf `--allow-empty` explicite.
- Signature configurée / absente.

**Hors périmètre**

- Composition de message par IA.
- Commit partiel par fichier dans cette tâche (déjà couvert par le staging).

**Preuve attendue**

- Tests + capture de la sortie de hook.

## P1-T03 — Branches locales et distantes

**Objectif :** gérer le cycle de vie des branches sans perte.

**Dépend de :** P0-T04

**Livrables**

- Créer, checkout, renommer, supprimer.
- Branches distantes, upstream, comparaison.
- Préflight : branche courante, mergée, upstream, travail local.
- Actions groupées (suppression multiple) avec confirmation.

**Critères d'acceptation**

- Une branche non mergée exige une confirmation forte.
- Une branche courante ne peut pas être supprimée.
- Le checkout refuse si des modifications seraient écrasées.
- L'upstream est correctement affiché et modifiable.
- Aucune branche distante supprimée par erreur.

**Tests**

- Fixtures : branches mergées/non mergées, detached, upstream absent.
- Tests de refus.

**Hors périmètre**

- Drag & drop (P3).

**Preuve attendue**

- Tests d'état après chaque opération.

## P1-T04 — Fetch, pull et push

**Objectif :** synchroniser avec les remotes avec progression, annulation et erreurs claires.

**Dépend de :** P1-T03

**Livrables**

- Fetch, pull (ff-only/rebase selon config), push.
- Progression streamée et annulation.
- Détection de non-fast-forward.
- Force-with-lease uniquement explicite.
- Credential helper HTTPS et support SSH.
- Gestion des erreurs auth, host key, réseau.

**Critères d'acceptation**

- Progression visible pendant l'opération.
- Annulation : le dépôt reste dans un état valide ; le remote est revalidé.
- Un push non-fast-forward est refusé avec remédiation.
- Aucun force push sans confirmation.
- Aucun token dans la configuration du remote.

**Tests**

- Remote local simulé (bare) pour fetch/push.
- Échec d'auth, host key, réseau.
- Annulation en cours.

**Hors périmètre**

- Gestion de clés SSH.
- Pull avec stratégies exotiques.

**Preuve attendue**

- Démo de fetch/push + tests d'annulation.

## P1-T05 — Merge, rebase et conflits de base

**Objectif :** intégrer des branches et gérer les conflits sans perte.

**Dépend de :** P1-T03, P1-T04

**Livrables**

- Merge et rebase avec préflight.
- Détection de conflit, liste des fichiers.
- Marquage résolu, `continue`, `abort`, `skip`.
- Ouverture dans l'éditeur/merge tool externe.
- Affichage permanent de l'état intermédiaire.
- Reprise après redémarrage.

**Critères d'acceptation**

- Un merge sans conflit aboutit ou crée un commit selon la configuration.
- Un conflit est visible et bloque les actions incompatibles.
- `abort` restaure l'état d'avant l'opération (ou signale ce qui ne peut pas l'être).
- `continue` fonctionne après résolution.
- Aucun travail local non lié n'est perdu.

**Tests**

- Fixtures de conflits merge/rebase.
- Abort/continue/skip.
- Redémarrage pendant un conflit.

**Hors périmètre**

- Résolution 3 panneaux (P2).
- Rebase interactif (P2).

**Preuve attendue**

- Tests d'état + captures.

## P1-T06 — Stash

**Objectif :** mettre de côté et restaurer du travail sans perte.

**Dépend de :** P1-T01

**Livrables**

- Créer, lister, appliquer, pop, drop.
- Stash visible dans le graphe.
- Gestion des conflits de pop.
- Message de stash.

**Critères d'acceptation**

- Un stash créé est retrouvé après redémarrage.
- Un pop en conflit laisse le stash intact.
- Un drop demande confirmation et conserve une référence de récupération.
- Aucun fichier non suivi perdu sans choix explicite.

**Tests**

- Fixtures stash avec modifications staged/unstaged/untracked.
- Conflit de pop.
- Drop et récupération.

**Hors périmètre**

- Stash partiel par fichier (optionnel, seulement si mesuré utile).

**Preuve attendue**

- Tests d'état.

## P1-T07 — Multi-dépôts

**Objectif :** travailler sur plusieurs dépôts sans fuite d'état ni de mémoire.

**Dépend de :** P0-T03

**Livrables**

- Onglets de dépôts, récents, favoris.
- Sessions isolées, fermeture propre.
- Indicateur d'activité par onglet.
- Changement rapide sans rechargement complet inutile.

**Critères d'acceptation**

- Cinq dépôts ouverts en alternance : pas de fuite mesurable, pas d'état croisé.
- La fermeture libère watcher, caches et processus.
- Les erreurs d'un dépôt n'affectent pas les autres.
- L'onglet actif est restauré au redémarrage.

**Tests**

- PERF-09.
- Test de fermeture et de fuite.
- Test d'isolation des erreurs.

**Hors périmètre**

- Workspaces (P3).

**Preuve attendue**

- Mesures mémoire + tests.

## P1-T10 — GitLab : liste et création de MR

**Objectif :** gérer les MR depuis l'application.

**Dépend de :** P0-T07

**Livrables**

- Liste des MR (mes MR, à reviewer, assignées, projet).
- Détail minimal (titre, branches, auteurs, labels, statut).
- Création depuis une branche poussée.
- Ouverture dans le navigateur.
- Association dépôt ↔ projet.
- Gestion des erreurs 401/403/404/409/422.

**Critères d'acceptation**

- La liste est paginée et filtrée correctement.
- La création échoue proprement si la branche n'est pas poussée.
- Le formulaire gère titre, description, cible, draft, suppression de source.
- Aucun token dans l'UI ou les logs.
- Hors ligne : dernières données en cache, aucune mutation en file.

**Tests**

- Contrat HTTP + instance de test.
- Création réelle sur projet de test.
- Sécurité des artefacts.

**Hors périmètre**

- Discussions inline, approvals, merge (P2).

**Preuve attendue**

- Parcours complet filmé + tests.

## P1-T12 — Sécurité des actions destructives

**Objectif :** garantir zéro perte silencieuse avant l'undo complet.

**Dépend de :** P1-T01, P1-T03, P1-T05

**Livrables**

- Préflight centralisé.
- Dialogues de confirmation avec conséquences exactes.
- Aucune sauvegarde applicative : confirmation renforcée et mention explicite de l'irréversibilité.
- Refus si état incohérent.
- Journal des actions destructives.

**Critères d'acceptation**

- Toute action de la matrice §2 de [07-reliability-security](../07-reliability-security.md) est couverte.
- Le nombre de fichiers/commits concernés est affiché.
- Aucun fichier non suivi n'est supprimé par l'application.
- Toute action irréversible est identifiée comme telle avant exécution.

**Tests**

- Matrice complète.
- Disque plein, permissions, état incohérent.

**Hors périmètre**

- Undo/redo complet (P3).

**Preuve attendue**

- Tests + captures des dialogues.
