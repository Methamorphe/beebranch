# P0 — Task cards

Each card is self-contained. One card = one PR. Do not expand the scope.

---

## P0-T01 — Workspace scaffolding, Tauri 2 and CI

**Objective:** have an empty application that launches on all three OSes, with green pipelines and crate boundaries respected.

**Depends on:** —

**Deliverables**

- Cargo workspace: `core`, `git`, `gitlab`, `store`, `app`, `bench`.
- Minimal Tauri 2 application with a window and a home page.
- **React 19.3 + TypeScript + Vite** frontend, build, lint, typecheck.
- Tauri configuration: restrictive CSP, minimal capabilities.
- Structured logging (`tracing`), app data directories.
- CI: format, clippy `-D warnings`, tests, build, Windows/macOS/Linux matrix.
- Git fixture script (skeleton).

**Steps**

1. Create the workspace and empty crates with the dependency rules.
2. Initialize Tauri 2 and the frontend.
3. Add logging and directory management.
4. Add CI and the build cache.
5. Verify launch on all three OSes.

**Acceptance criteria**

- `cargo build`, `cargo test`, `cargo clippy -- -D warnings` pass.
- The frontend compiles and launches.
- The application opens a window on Windows, macOS and Linux.
- The CSP prohibits remote scripts; no unnecessary capabilities.
- No network access at startup.

**Tests**

- Launch smoke test (CI).
- Trivial unit test per crate to validate the structure.
- CI matrix verification.

**Out of scope**

- Any Git or GitLab functionality.
- Design system.

**Expected evidence**

- Green CI logs on all three OSes; screenshot of the empty window.

## P0-T02 — Git process layer

**Objective:** centralize all Git execution in a safe, observable and cancellable module.

**Depends on:** P0-T01

**Deliverables**

- `git::process`: `CommandSpec`, binary resolution, subcommand/option allowlist.
- Shell-free argv construction.
- Controlled environment (`GIT_TERMINAL_PROMPT=0`, `GIT_PAGER=cat`, etc.).
- Bounded `stdout`/`stderr` capture, exit code, duration.
- Streaming and cancellation for long-running operations.
- Centralized redaction.
- `git::capability`: version and available options.

**Steps**

1. Define the types and allowlist.
2. Implement launch, capture and timeout.
3. Implement streaming and cancellation (Unix/Windows).
4. Add redaction and `tracing` spans.
5. Unit and integration tests on fixtures.

**Acceptance criteria**

- No command runs through a shell.
- An argument containing spaces, quotation marks or `;` is never interpreted.
- A long-running command can be cancelled; the process is stopped.
- Output is bounded and secrets are redacted.
- Windows does not open a console.
- Errors return a stable code.

**Tests**

- Unit: argv construction, allowlist, redaction.
- Integration: `git --version`, `status`, cancelled command, failed command.
- Platform: cancellation on all three OSes.

**Out of scope**

- Domain commands (status, log, etc.).

**Expected evidence**

- Passing tests + demonstration of cancelling a dummy `fetch` or a `sleep` launched by a test helper.

## P0-T03 — Repository discovery and session

**Objective:** open a repository or worktree, determine its status, and maintain a consistent session.

**Depends on:** P0-T02

**Deliverables**

- Discovery: worktree, git dir, common dir, bare, inside-worktree.
- `RepoSession`: identifier, paths, generation, status, mutation queue.
- Status detection: merge, rebase, cherry-pick, revert, bisect, conflicts, detached, unborn, locks.
- Watcher with debounce and targeted invalidation.
- Session registry and clean shutdown.

**Steps**

1. Implement discovery and path validation.
2. Implement status detection via `rev-parse --git-path` and `status`.
3. Implement the mutation queue and generation.
4. Implement the watcher and invalidation.
5. Tests on fixtures (worktree, submodule, intermediate states).

**Acceptance criteria**

- Opening a repository, worktree and submodule produces the correct session.
- Intermediate states are detected correctly.
- An external change invalidates the affected areas.
- Closing leaves no watcher or process behind.
- An invalid path returns `repo.not_git`.

**Tests**

- Fixtures: simple repository, worktrees, submodule, merge in progress, rebase, detached, bare.
- Shutdown and resource leak test.
- External change test.

**Out of scope**

- Complete UI; history reading.

**Expected evidence**

- Fixture test report + invalidation log.

## P0-T04 — Read model

**Objective:** provide the frontend with the data needed for the graph, status and diff, with pagination and stable types.

**Depends on:** P0-T03

**Deliverables**

- Refs: local/remote branches, tags, remotes, upstream, HEAD.
- Status: `--porcelain=v2 -z` parsing, conflicts, untracked.
- Log: page of commits with parents, author, date, refs, subject.
- Commit details: message, files, stats.
- Diff: unified parser, hunks, binary, missing newline.
- Serialized and versioned DTOs.

**Steps**

1. Implement the parsers with unit tests.
2. Implement the commands and DTOs.
3. Add pagination and limits.
4. Wire up the Tauri read commands.
5. Measure the times for each read (input for P0-T08).

**Acceptance criteria**

- Data is correct on all fixtures.
- No command implicitly loads the entire history or all files.
- A stale read is identifiable by its generation.
- Binary cases, renames, CRLF and Unicode are handled.
- Errors are typed.

**Tests**

- Unit: each parser, edge cases.
- Integration: commands on fixtures, comparison with command-line `git`.
- Contract: DTO shapes.

**Out of scope**

- UI rendering; interactions.

**Expected evidence**

- Read timing table + passing tests.

## P0-T05 — Virtualized graph prototype

**Objective:** demonstrate that the graph handles the load and that the topology is correct.

**Depends on:** P0-T04

**Deliverables**

- Canvas rendering with visible rows + overscan.
- Rust-side lane calculation from parents.
- Incremental loading by page.
- Basic selection and highlighting.
- Frame timing instrumentation.
- Report on `linear-100k`, `merges-deep`, `branches-5k`.

**Steps**

1. Define the row and segment model.
2. Implement the lane algorithm with tests.
3. Implement canvas rendering and virtualization.
4. Wire up pagination and append.
5. Measure and adjust.

**Acceptance criteria**

- Correct topology for merges, octopus, dead branches.
- Measured scrolling, p95 and missed frames reported.
- Bounded memory for 200k commits.
- No full recalculation on append.
- No DOM node per commit.

**Tests**

- Unit: lanes on topology fixtures.
- Visual: screenshots on the corpus.
- Performance: PERF-02, PERF-03.

**Out of scope**

- Contextual actions, advanced filters, drag & drop.

**Expected evidence**

- JSON report + screenshot + rendering decision.

## P0-T08 — Benchmark harness

**Objective:** make performance measurable and comparable before any optimization.

**Depends on:** P0-T02, P0-T04, P0-T05, P0-T06

**Deliverables**

- Deterministic corpus generator.
- Harness for PERF-01..12.
- Versioned JSON report.
- Initial baseline.
- CI job (reduced in PRs, full in nightly runs).

**Steps**

1. Generator and seeds.
2. Backend harness (commands, parsing).
3. Frontend harness (opening, scrolling).
4. Report and baseline storage.
5. CI integration and thresholds.

**Acceptance criteria**

- A run is reproducible on a given machine.
- Metrics include p50/p95, memory and IPC bytes.
- A regression beyond the threshold fails in CI.
- 1M-commit results are nightly.

**Tests**

- The harness fails if the corpus is missing.
- The report is valid and comparable.

**Out of scope**

- Optimizations.

**Expected evidence**

- Baseline report + CI job.

## P0-T09 — Errors and recovery

**Objective:** make failures understandable and intermediate states recoverable.

**Depends on:** P0-T02, P0-T03

**Deliverables**

- `AppError` and taxonomy.
- Mapping of known Git errors.
- SQLite operation log.
- Detection of interrupted operations at startup.
- Recovery panel.
- Detail redaction.

**Steps**

1. Define codes and categories.
2. Implement mapping and tests.
3. Implement the log.
4. Implement recovery and the panel.
5. Fault injection.

**Acceptance criteria**

- Each known error has a stable code and remediation.
- A kill during an operation is detected on restart.
- No lock is automatically removed.
- No error is silent.
- Details are redacted.

**Tests**

- Error fixtures (auth, conflict, lock, dirty, identity, signature, etc.).
- Kill during fetch/commit/rebase.
- Artifact verification.

**Out of scope**

- Undo.

**Expected evidence**

- Fault injection tests + panel screenshot.
