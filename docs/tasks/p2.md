# P2 — Task cards

**Status: implemented in version 0.3.0.** Evidence and card → code/tests mapping: [docs/reviews/p2-review.md](../reviews/p2-review.md).

Compact cards. Same DoD as P0/P1: real behavior, tests, evidence.

---

## P2-T01 — Interactive rebase

**Depends on:** P1-T05

**Deliverables:** application-generated todo, `GIT_SEQUENCE_EDITOR`/`GIT_EDITOR` helper, pick/reword/squash/drop actions, reordering, conflicts, abort/continue, plan reset.

**Acceptance criteria**

- The todo matches the approved plan exactly.
- Reword and squash produce the expected messages.
- A conflict is visible and manageable.
- No corrupted todo, no base commit deleted.
- Works on Windows/macOS/Linux.

**Tests:** rebase fixtures, conflicts, reword/squash, crash during rebase.

**Out of scope:** drag & drop (P3).

---

## P2-T02 — 3-panel conflict resolution

**Depends on:** P2-T01, P1-T05

**Deliverables:** base/ours/theirs/output, editing, block selection, marking as resolved, saving, navigation.

**Acceptance criteria**

- The three versions come from the correct Git stages.
- Editing does not corrupt the markers.
- Marking as resolved updates the index.
- A binary or oversized file is handled explicitly.
- Abort remains possible.

**Tests:** text conflicts, binaries, large files, missing newline, CRLF.

---

## P2-T03 — Advanced cherry-pick and revert

**Depends on:** P1-T05

**Deliverables:** ordered multiple selection, range cherry-pick, range revert, conflicts, continue/abort/skip, history.

**Acceptance criteria**

- Commit order is respected.
- Conflicts are handled as in a merge.
- No commit lost without confirmation.
- Status is consistent after restart.

**Tests:** multi-commit fixtures, conflicts, abort.

---

## P2-T04 — Worktrees

**Depends on:** P0-T03

**Deliverables:** listing, creation, opening, lock/unlock, deletion, status per worktree, opening in a new tab.

**Acceptance criteria**

- Each worktree has its own session and status.
- Deletion refuses a dirty worktree without confirmation.
- Shared refs are consistent.
- No cache mixed between worktrees.

**Tests:** multi-worktree fixtures, dirty deletion, lock.

---

## P2-T05 — File history and blame

**Depends on:** P0-T04

**Deliverables:** per-file history, rename tracking, line-by-line blame, navigation to commit.

**Acceptance criteria**

- Rename tracking works for a file.
- Blame is correct on modified lines.
- Large files are capped.
- Navigation preserves context.

**Tests:** rename fixtures, mixed lines, large files.

---

## P2-T06 — Command palette and shortcuts

**Depends on:** P1

**Deliverables:** command palette, fuzzy search, repository context, configurable shortcuts, help.

**Acceptance criteria**

- All frequent actions are accessible.
- Unavailable commands are explained.
- Shortcuts do not cause silent conflicts.
- The palette stays fast.

**Tests:** UI tests, shortcut conflicts.

---

## P2-T07 — In-depth search

**Depends on:** P1-T08

**Deliverables:** search by path, content (with limits), author, date, explicit scope.

**Acceptance criteria**

- Content search is bounded and cancellable.
- Results are paginated.
- No freeze on a large repository.
- The scope is visible.

**Tests:** fixtures, performance, cancellation.

## P2-T08 — GitLab: inline discussions

**Depends on:** P1-T10

**Deliverables:** reading/writing positioned discussions, resolution, display in the diff.

**Acceptance criteria**

- The position uses the SHAs from `diff_refs`.
- Threads are grouped correctly.
- A 422 error is explained.
- No raw HTML rendered.

**Tests:** HTTP contract, sanitization, positions.

## P2-T09 — GitLab: approvals and merge

**Depends on:** P1-T10

**Deliverables:** approval, merge with strategy, auto-merge, feature detection.

**Acceptance criteria**

- Unavailable endpoints are hidden.
- Merge uses the current SHA.
- 405/406/409 errors are explained.
- Confirmation before merge.

## P2-T10 — GitLab: jobs and logs

**Depends on:** P1-T11

**Deliverables:** job list, status, paginated logs, web link.

**Acceptance criteria**

- Logs are loaded on demand.
- Large logs are capped.

## P2-T11 — Submodules

**Depends on:** P0-T03

**Deliverables:** panel, add, init, update, commit pointer, statuses.

**Acceptance criteria**

- Git statuses are reflected correctly.
- A pointer update is explicit.
- No submodule silently modified.
- Recursive operations are bounded.

**Tests:** local submodule fixture, update, pointer.

---

## P2-T12 — Advanced tags and remotes

**Depends on:** P1-T03

**Deliverables:** annotated tags, tag push, remote management, URLs, prune.

**Acceptance criteria**

- An annotated tag preserves its message and tagger.
- A tag push is explicit.
- A misconfigured remote produces a clear error.
- No remote deleted without confirmation.

**Tests:** tag/remote fixtures.

---

## P2-T13 — Profiles

**Depends on:** P1-T07

**Deliverables:** Git identity, preferences, tabs, one active GitLab instance per profile.

**Acceptance criteria**

- Switching profiles does not affect the others.
- The identity used is visible before commit.
- Integrations are isolated.
- No secret shared between profiles.

**Tests:** two profiles, two identities, switching.

---

## P2-T14 — Patches

**Depends on:** P1-T01

**Deliverables:** creation from working tree/commit, application, conflicts.

**Acceptance criteria**

- A created patch applies to an identical base.
- Unsupported binaries are refused explicitly.
- A conflict does not alter the worktree.
- The patch source is visible.

**Tests:** patch fixtures, conflict, binary.
